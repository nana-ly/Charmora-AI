# ShopGuide RAG 后端技术文档

本文档说明当前后端的模块边界、核心链路、接口约定和后续扩展方式。README 只保留快速运行和验收信息；维护、扩展或联调时优先阅读本文档。

---

## 1. 后端定位

后端负责把用户的自然语言购物需求转换成可展示的商品推荐结果，并为 Android 客户端提供稳定 JSON 接口。

当前已实现：

- FastAPI HTTP 服务。
- 本地 JSON 商品数据加载。
- 规则版需求解析：品类、预算、品牌、关键词。
- 结构化候选筛选。
- 关键词检索排序。
- 商品卡片响应组装。
- 异常和空结果兜底。
- 可选 LLM 推荐理由生成。
- 轻量多轮 Agent：推荐、偏好调整、解释、追问。
- LangGraph 首版 Runner：通过 `AGENT_RUNNER=langgraph` 灰度切换 `/chat` 编排层。
- RAG 向量检索调试接口和推荐链路向量召回。
- 事件级 SSE 流式对话接口。

当前未实现但已预留接口：

- 持久化会话记忆。
- 图片上传和多模态检索。
- 商品详情、反馈、知识库管理等扩展接口。

## 2. 模块结构

```text
backend/main.py
  FastAPI 应用入口，定义 /、/health、/recommend、/rag/search、/chat、/chat/stream。

backend/recommendation.py
  兼容入口，继续导出旧路径下的推荐函数和常量。

backend/core/
  应用配置和统一错误类型。

backend/schemas/
  Pydantic 数据模型，包括推荐请求、商品卡片和对话响应。

backend/recommendation_core/
  推荐核心链路：数据加载、需求解析、候选筛选、响应组装、理由生成和兜底策略。

backend/retrieval/
  检索层抽象：Retriever 协议、KeywordRetriever 实现、VectorRetriever RAG 适配器。

backend/llm/
  OpenAI 兼容客户端和可选推荐理由服务。

backend/agent/
  多轮导购 Agent，包括内存会话状态、规则意图策略、推荐工具、Runner 工厂、规则版编排器和 LangGraph 首版编排器。

backend/tests/
  后端接口、推荐链路、检索层、LLM 理由层和 Agent 测试。
```

整体依赖方向：

```text
FastAPI 路由
  -> schemas
  -> recommendation_core / agent
  -> retrieval / llm
  -> 本地商品数据集
```

```http
GET  /

POST /rag/search

```

接口字段的详细契约见：[API 接口契约](api.md)。

```text
items[].product_id
items[].title
items[].brand
items[].price
items[].reason
items[].evidence
```

后端可以继续增加字段，但不要删除或改名这些字段。

## 4. 推荐链路

`POST /recommend` 通过 `main.run_recommendation(query)` 调用推荐链路完成单轮推荐。

```text
request.query
  -> extract_filters(query)
  -> choose_candidates(products, filters)
  -> 根据 RETRIEVER_MODE 选择 KeywordRetriever 或 VectorRetriever
  -> build_response_item(query, retrieved_item)
  -> generate_reason(...)
  -> return {"query", "filters", "items"}
```

核心职责：

1. `extract_filters` 从自然语言中解析品类、预算、品牌和关键词。
2. `choose_candidates` 用结构化条件筛选本地商品候选集。
3. 检索层对候选商品做关键词排序或 RAG 向量召回。
4. `build_response_item` 把检索结果转换为前端商品卡片字段。
5. `generate_reason` 生成推荐理由，优先使用注入的理由服务，否则使用模板理由。
6. 链路为空或异常时返回 `fallback_items(query)`，保证客户端有稳定内容可展示。

## 5. 数据与筛选

商品数据来自仓库根目录下的本地数据集：

```text
ecommerce_agent_dataset/*/data/*.json
```

加载入口：

```text
backend/recommendation_core/data.py
```

当前商品在模块加载时读取并缓存到 `products`。这适合本地演示和最小闭环；如果后续接入数据库或商品服务，可以优先替换 `load_products()` 或提供新的 `product_source`，上层推荐链路不需要大改。

当前规则支持的主要品类：

```text
数码电子
美妆护肤
服饰运动
食品生活
```

预算解析支持类似：

```text
预算9000以内
9000以下
不超过9000
9000左右
```

## 6. 检索层

检索层通过 `Retriever.search()` 暴露统一接口：

```python
def search(
    query: str,
    candidates: list[dict] | None = None,
    top_k: int = 3,
) -> list[RetrievalResult]:
    ...
```

`RetrievalResult` 包含：

```text
product   原始商品字典
evidence  可展示给用户的中文匹配依据
score     检索或排序分数
```

当前实现包括 `KeywordRetriever` 和 `VectorRetriever`：

- `KeywordRetriever` 拼接商品标题、品牌、品类、子品类和营销描述作为可检索文本，按关键词命中数和价格排序。
- `VectorRetriever` 通过 `rag/shopguide_rag/chroma_store.ProductVectorStore` 查询 ChromaDB 商品向量索引，返回带 score 和 evidence 的 `RetrievalResult`。
- `RETRIEVER_MODE=vector` 时推荐链路优先使用向量检索；初始化或查询失败时自动回退关键词检索，避免 `/recommend` 和 `/chat` 返回 500。

RAG 调试入口：

```http
POST /rag/search
```

该接口只用于本地检查向量召回、score 和 evidence，不作为 Android 主依赖。Agent 编排层不直接读取向量库或 embedding 配置，只通过 `RecommendationTool` 间接消费推荐结果。

## 7. LLM 理由层

LLM 是增强能力，不是推荐链路的硬依赖。

配置入口：

```text
backend/core/config.py
backend/.env.example
```

相关环境变量：

```text
LLM_ENABLED=false
LLM_API_KEY=
LLM_BASE_URL=https://api.openai.com/v1
LLM_MODEL=gpt-4o-mini
LLM_TIMEOUT_SECONDS=8
```

调用条件：

```text
LLM_ENABLED=true
且 LLM_API_KEY 非空
```

兜底规则：

- 未启用 LLM 时，直接返回模板理由。
- API Key 缺失时，直接返回模板理由。
- LLM 调用失败时，吞掉异常并返回模板理由。
- LLM 失败不影响 `/recommend` 和 `/chat` 的商品列表返回。

## 8. 多轮 Agent 链路

`POST /chat` 通过 `AGENT_RUNNER` 选择 Runner 编排一轮对话。

```env
AGENT_RUNNER=simple
```

`simple` 是默认稳定模式，使用规则版 `SimpleAgentRunner`；`langgraph` 使用 LangGraph 首版 `LangGraphAgentRunner`。两种模式下 `/chat` 和 `/chat/stream` 的请求、响应字段保持兼容。

```text
session_id + message
  -> InMemoryConversationStore.get_or_create(session_id)
  -> AgentPolicy.detect_intent(message)
  -> RecommendationTool.run(...)
  -> 更新 last_query、last_filters、last_items、preferences
  -> return ChatResponse
```

LangGraph 首版职责：

```text
detect_intent -> recommend/update_preference/explain/clarify -> finalize
```

- 只替换 Agent 编排层，不实现检索、排序或 RAG 索引逻辑。
- 推荐节点只调用 `RecommendationTool`，继续复用 `main.run_recommendation()`。
- 图节点保存清晰中文注释，便于多人协作时理解状态流转和跨模块边界。

当前支持的意图：

```text
recommend          明确推荐需求
update_preference  基于上一轮调整偏好，例如“再便宜一点”
explain            解释上一轮推荐，例如“为什么推荐第一款”
clarify            信息不足时追问品类、预算和偏好
```

当前会话状态保存在内存中，适合本地开发和演示。服务重启后状态会丢失。生产化时可以用同样的 `get_or_create()`、`save()` 思路替换成 Redis、数据库或其他持久化存储。

## 9. 兜底策略

候选筛选为空时，`choose_candidates` 会逐步放宽条件：

```text
1. 品类 + 预算 + 品牌
2. 去掉品牌限制
3. 去掉预算限制，只保留品类
4. 全库检索
```

推荐结果为空或链路异常时，`recommend_products` 会返回 `fallback_items(query)`。

兜底商品仍保持稳定字段：

```json
{
  "product_id": "fallback_001",
  "title": "通用推荐商品 1",
  "brand": "系统推荐",
  "price": 0,
  "reason": "当前根据「用户需求」返回兜底推荐，真实检索结果暂不可用。",
  "evidence": "后端兜底逻辑触发。"
}
```

## 10. 测试与检查

在仓库根目录运行后端测试：

```powershell
python -m pytest backend/tests -q
```

在 `backend` 目录运行 Ruff：

```powershell
cd backend
uv run ruff check .
```

测试覆盖重点：

- `/` 和 `/health` 基础接口。
- `/recommend` 返回真实推荐链路结果和稳定商品字段。
- `/chat` 返回 Agent 回复、商品列表和状态快照。
- `/chat` 在 `AGENT_RUNNER=simple` 和 `AGENT_RUNNER=langgraph` 两种模式下保持响应契约兼容。
- `/chat/stream` 事件顺序保持 `start -> delta -> items -> state -> done`，异常时为 `start -> error -> done`。
- `/rag/search` 返回向量召回调试结果，推荐链路向量失败时回退关键词检索。
- `recommendation_core` 的筛选、排序、响应组装和兜底。
- `retrieval` 的关键词检索和抽象协议。
- `llm` 的可用性判断、模板兜底和失败回退。
- `agent` 的意图判断、状态更新和工具调用。

## 11. 扩展建议

后续扩展时建议保持以下边界：

- 接入向量库时优先替换 `retrieval/`，继续返回 `RetrievalResult`。
- 扩展 LangGraph 时优先新增 `backend/agent/graph/` 节点或工具，不把图编排逻辑塞进 `backend/main.py`。
- 接入真实商品服务时优先替换 `recommendation_core/data.py`，不要让路由层直接依赖数据源。
- 增强意图识别时替换 `AgentPolicy.detect_intent()`，继续返回 `AgentDecision`。
- 持久化会话时替换 `InMemoryConversationStore`，保持 `get_or_create()` 和 `save()` 行为。
- 增加接口字段时使用可选字段扩展，不修改 Android 已依赖的商品卡片字段。
