# Android 原生 3 天最小闭环方案

> 当前状态说明：本文是早期 3 天 MVP 方案，保留用于回溯最小闭环设计。当前代码已经扩展到 `/chat` 多轮导购、`/chat/stream` SSE 流式输出、商品扩展字段、购物车 UI、语音输入和商品详情页；接口契约以 `docs/api.md` 为准，后端实现以 `docs/后端技术文档.md` 和 `backend/README.md` 为准。

## 一、重新定义目标

本项目第一阶段只做：

> Android 原生客户端 + RAG 后端 + 单轮导购 + 模糊推荐 + 条件筛选。

第一版系统不做复杂聊天机器人，而是做一个“AI 导购推荐页”。

用户输入一句自然语言需求，例如：

```text
预算9000以内，想买拍照好、适合剪视频的手机
```

系统完成：

```text
用户输入需求
        ↓
后端理解条件
        ↓
从商品数据中筛选候选商品
        ↓
RAG 检索商品知识
        ↓
大模型生成推荐理由
        ↓
Android 展示商品推荐列表
```

## 二、第一版功能范围

### 必须实现

| 功能 | 说明 |
|---|---|
| Android 原生页面 | 输入需求，展示推荐结果 |
| 单轮问答 | 不保存上下文，不做多轮追问 |
| 模糊推荐 | 用户说“拍照好”“适合敏感肌”“夏天凉快”也能推荐 |
| 条件筛选 | 支持品类、预算、品牌、关键词 |
| 商品卡片 | 展示名称、品牌、价格、推荐理由 |
| 后端接口 | Android 调用 `/recommend` 接口 |
| RAG 检索 | 基于已有 JSON 商品知识检索 |
| 简单评测 | 用 10 个问题验证推荐效果 |

### 暂时不做

| 功能 | 原因 |
|---|---|
| 多轮对话 | 先做单轮闭环 |
| 流式输出 | 推荐列表一次性返回即可 |
| 图片输入 | 当前 images 目录为空，先不做 |
| iOS | 已明确只做 Android |
| 复杂 Agent | 固定流程更稳 |
| 购物车/支付 | 与导购闭环无关 |

以上范围描述的是早期 MVP。当前 Android 代码默认优先调用 `POST /chat/stream`，当 SSE 不可用时回退 `POST /chat`；`/recommend` 仍保留为单轮推荐接口。


## 八、条件筛选设计

### 第一版支持的筛选条件

| 条件 | 示例 |
|---|---|
| 品类 | 手机、护肤、T恤、咖啡 |
| 预算上限 | 9000以内、100以下、300左右 |
| 品牌 | Apple、雅诗兰黛、优衣库、三顿半 |
| 场景关键词 | 拍照、剪视频、敏感肌、夏天、通勤、新手 |

### 筛选逻辑

```text
1. 从 query 中提取 max_price
2. 从 query 中识别 category
3. 从 query 中识别 brand
4. 用结构化条件过滤商品
5. 如果过滤结果为空，放宽条件
6. 用向量检索做模糊匹配
7. 返回 Top 3
```

### 放宽策略

如果没有结果：

```text
先去掉品牌限制
再放宽价格 20%
再只保留品类
最后全库检索
```

这样可以避免返回空。

## 九、推荐排序逻辑

第一版不做复杂推荐算法，按简单分数排序：

```text
score = 向量相似度分
      + 价格匹配分
      + 品类匹配分
      + 品牌匹配分
```

示例：

| 匹配项 | 加分 |
|---|---|
| 品类匹配 | +0.2 |
| 价格低于预算 | +0.2 |
| 品牌命中 | +0.2 |
| 标题 / 描述包含关键词 | +0.1 |

最后取：

```text
Top 3
```
