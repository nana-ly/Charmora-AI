# ShopGuide Lifestyle：产品定义与 MVP 边界

## 1. 产品定义

ShopGuide Lifestyle 是一个面向生活方式零售场景的 AI 原生导购与交易闭环原型。它不是单一“饰品客服”，而是类似 MINISO 的综合生活杂货店：覆盖首饰与发饰、挂件与毛绒、包袋与化妆包、美妆工具、文具、家居日用、收纳及礼赠等品类。

核心价值是把用户模糊、跨品类的购物意图（如“50 元内送同学的可爱礼物”“适合通勤的小包和配套挂件”）转化为可执行的筛选条件，并完成“发现—比较—决策—购物车—确认—下单—订单状态”的完整闭环；同时为运营人员提供商品导入、校验、发布和库存维护能力。

## 2. 三条核心闭环

### 消费者闭环

浏览/搜索/对话 → Agent 澄清预算、用途、风格、对象和禁忌 → 检索与排序 → 给出有依据的推荐、对比及替代项 → 加入购物车 → 校验价格与库存 → 用户二次确认 → 模拟支付 → 生成订单并展示状态。

### 商家闭环

手工录入或导入 CSV/XLSX/JSON → 字段和重复项校验 → 预览与错误报告 → 人工确认发布 → 维护价格、库存和上下架状态 → 同步检索索引 → 商品可被搜索和 Agent 调用。

### 可控 Agent 闭环

Agent 只通过有权限、可审计的工具读取商品、比较、操作购物车和发起订单；价格、库存、订单金额以数据库为准。涉及下单等关键动作必须明确确认，失败时给出原因及可恢复路径，不虚构商品、库存、优惠或订单结果。

## 3. 数据与素材规则

- 现有样例、扩充的模拟商品和后续导入商品使用统一字段，但通过 `data_origin`、`source_batch_id`、`is_synthetic`、`image_source`、`image_license` 明确区分，可按批次撤回，不能静默混杂。
- 第一阶段品类：首饰/发饰、挂件/毛绒、包袋/化妆包、美妆工具、文具、家居日用/收纳、礼赠组合。暂不经营需要复杂资质或功效声明的真实化妆品。
- 搜索引擎只用于发现候选图片，不代表图片可自由使用。演示素材应使用明确允许复用的图片，下载到项目资源中并记录来源、作者和许可，不直接盗链。

## 4. MVP 包含

- 商品分类、搜索、筛选、详情、上下架和库存状态。
- 管理端商品导入、校验、预览、发布及错误报告。
- 购物车、库存复核、模拟支付、订单创建和订单状态查询。
- Agent 的需求澄清、推荐解释、商品对比、替代推荐、加购和确认下单。
- 推荐与交易关键路径的确定性测试、Agent 行为评测及操作日志。
- Android 客户端与 FastAPI/LangGraph 后端贯通，优先完成端到端演示，不先追求大规模商品量。

## 5. MVP 明确不做

- 真实支付、真实物流、发票、复杂退款及外部商城账号体系。
- 多商户平台、直播电商、完整营销中心和大规模个性化推荐系统。
- 自动抓取第三方商城商品或未经许可的图片；随机拼接来源不明的数据。
- Agent 自主修改价格/库存、绕过确认下单，或用大模型生成数据库中不存在的商品事实。

## 6. 验收标准

- 每个商品都能追溯数据来源；模拟数据在界面或管理端可识别、可筛选、可整批撤回。
- 导入错误能定位到具体行和字段，未通过校验的数据不能发布。
- Agent 推荐的商品真实存在且可解释；用户拒绝的条件在同一轮任务中得到遵守。
- 下单前重新校验价格和库存，未经明确确认不创建订单；失败不会产生伪成功状态。
- 从自然语言需求到订单状态展示可完整演示，核心自动化测试与评测可重复运行。

## 7. MVP 后续演进

退换货与履约 → 用户偏好记忆和个性化 → 图片/语音多模态选品 → 优惠与礼赠组合 → 外部商品/库存适配器 → 更完善的可观测性、权限、安全与运营分析。
